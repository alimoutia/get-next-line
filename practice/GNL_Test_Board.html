How to use this board

  • Work from the tester folder. It sits inside your repository, next to the project files, so your sources are ../get_next_line.c and ../get_next_line_utils.c. The Toolkit part says what every file does.
  • Set up once. chmod +x failtest.sh matrix.sh make_tests.sh, then ./make_tests.sh creates the test files in tests/.
  • Order that saves time. Build, then read files at BUFFER_SIZE 5, then ./matrix.sh, then stdin and bad fds, then failtest.sh at sizes 1 and 5. Always with -fsanitize=address.
  • Pass means silent. cmp prints nothing when two files are identical, matrix.sh ends with failed: 0, failtest.sh with bad runs: 0 / 80. Any other line is a lead: read it.
  • Own mains. A few rows need a small main of your own (calls after NULL, a closed fd, one line per call). Write them: that is the practice.
  • Linux for the malloc kit. --wrap does not exist in the macOS linker. Everything else works on both.
  • Edge rows are the ones that usually break a first attempt. The Evaluation part lists the questions to answer out loud. Tick state is saved in this browser only.

test_main.c

cc -Wall -Wextra -Werror -g -fsanitize=address -D BUFFER_SIZE=5 ../get_next_line.c ../get_next_line_utils.c test_main.c -o t

A tiny main you do not edit. It reads one file with your function and prints what comes back.

  1. Opens argv[1] read-only.
  2. Calls your function until it returns NULL.
  3. Prints each line with fwrite (so a line containing a \0 or no \n is printed exactly), frees it, and closes the file.

Your function is called GNL in the file. It defaults to get_next_line; for another name build with -DGNL=gnl.

Use it with cmp: ./t tests/three_nl.txt | cmp - tests/three_nl.txt. No output means the bytes are identical. /dev/stdin works as a file name, so pipes and the terminal can be tested with the same program.

#include <fcntl.h>
#include <stdlib.h>
#include <string.h>
#include <stdio.h>
#include <unistd.h>

#ifndef GNL
# define GNL get_next_line
#endif

char	*GNL(int fd);

int	main(int ac, char **av)
{
	int		fd;
	char	*line;

	if (ac < 2)
		return (1);
	fd = open(av[1], O_RDONLY);
	line = GNL(fd);
	while (line)
	{
		fwrite(line, 1, strlen(line), stdout);
		free(line);
		line = GNL(fd);
	}
	close(fd);
	return (0);
}

malloc_fail.c

cc ... malloc_fail.c -Wl,--wrap=malloc

Makes one chosen malloc fail, without touching your code.

The flag -Wl,--wrap=malloc tells the linker: every call to malloc in the program goes to __wrap_malloc instead. That function counts the calls. When the count equals the environment variable FAIL_AT, it returns NULL; otherwise it calls the real one (__real_malloc).

Try it by hand: FAIL_AT=3 ./failbin tests/three_nl.txt makes the 3rd malloc fail. Without FAIL_AT nothing fails.

Linux only. The linker on macOS has no --wrap. Run the kit on Linux (the school machines, a VM, or your CachyOS).

#include <stdlib.h>

void	*__real_malloc(size_t size);

static int	g_count;

void	*__wrap_malloc(size_t size)
{
	char	*at;

	at = getenv("FAIL_AT");
	if (at && ++g_count == atoi(at))
		return (NULL);
	return (__real_malloc(size));
}

failtest.sh

./failtest.sh "<your .c files WITHOUT a main>" <input file> <BUFFER_SIZE> [function name]

Runs the program 80 times, failing a different malloc each time, and judges every run.

For N = 1 to 80 it runs with FAIL_AT=N and checks three things:

  1. The output is a prefix of the input file (nothing invented, nothing skipped).
  2. If the output stops early, it stops on a whole line.
  3. The sanitizer printed no ERROR (no leak, no invalid access, no double free).

A bad run prints a line saying which check failed. The last line is bad runs: X / 80. You want 0.

Problems you may meet:

  • "exists but is not an executable file": run chmod +x failtest.sh.
  • "multiple definition of main": your files contain a main. Pass files without one; the kit brings its own.
  • "undefined reference to get_next_line": your function has another name. Give it as the 4th argument.
  • Nothing fails at big sizes: with a small file and BUFFER_SIZE bigger than the file, only a handful of mallocs happen. Use sizes 1 and 5 too.
#!/bin/sh
# Makes the Nth malloc fail, for N = 1..80, one run per N.
# usage: ./failtest.sh "<your .c files, WITHOUT a main>" <input file> <BUFFER_SIZE> [function name]
# example: ./failtest.sh "gnl.c gnl_utils.c" text.md 5 gnl
# A run is GOOD when the program does not crash, leaks nothing, and prints only
# a prefix of the input made of whole lines.
srcs=$1; file=$2; bs=$3; fn=${4:-get_next_line}
cc -g -fsanitize=address -D BUFFER_SIZE=$bs -DGNL=$fn $srcs test_main.c malloc_fail.c \
	-Wl,--wrap=malloc -o failbin || exit 1
size=$(wc -c < $file)
bad=0
for n in $(seq 1 80); do
	FAIL_AT=$n ./failbin $file > fo.txt 2> fe.txt
	sz=$(wc -c < fo.txt)
	if ! head -c $sz $file | cmp -s - fo.txt; then
		echo "N=$n: output is NOT a prefix of the input"; bad=$((bad+1)); continue
	fi
	if [ $sz -gt 0 ] && [ $sz -lt $size ] && [ "$(tail -c 1 fo.txt | od -An -c | tr -d ' ')" != '\n' ]; then
		echo "N=$n: output stops in the middle of a line"; bad=$((bad+1)); continue
	fi
	if grep -q "ERROR" fe.txt; then
		echo "N=$n: sanitizer: $(grep -m1 -o 'ERROR: [A-Za-z]*' fe.txt)"; bad=$((bad+1))
	fi
done
echo "bad runs: $bad / 80"

make_tests.sh and matrix.sh

./make_tests.sh then ./matrix.sh "../get_next_line.c ../get_next_line_utils.c"

The files to read and the loop that reads all of them at every size.

make_tests.sh writes the 13 files in tests/ that the board names. matrix.sh builds your code with AddressSanitizer for the sizes 1, 2, 5, 42, 9999 and 10000000, runs every file, and prints a line for each failure: the size, the file and the reason (output differs or the sanitizer error). The last line is failed: 0 when everything is good. It takes a few seconds.

#!/bin/sh
# Creates the test files in ./tests (safe to run again).
mkdir -p tests && cd tests || exit 1
: > empty.txt                                   # 0 bytes
printf 'hello\n' > one_nl.txt                   # one line, ends with \n
printf 'hello' > one_nonl.txt                   # one line, NO \n at the end
printf '\n' > only_nl.txt                        # just a newline
printf '\n\n\n\n' > many_empty.txt               # four empty lines
printf 'one\ntwo\nthree\n' > three_nl.txt
printf 'one\ntwo\nthree' > last_nonl.txt        # last line has no \n
printf '1234\n5678\n' > bs5_exact.txt           # lines exactly BUFFER_SIZE=5 long (with the \n)
printf '123\n1234\n12345\n' > bs5_around.txt   # lengths 4, 5, 6 with the \n: BUFFER_SIZE-1, exact, +1
printf 'a\r\nb\r\n' > crlf.txt                   # Windows line ends: \r is just a character
printf '   \n \n\n' > spaces.txt
head -c 20000 /dev/zero | tr '\0' 'x' > long_line.txt; printf '\nend\n' >> long_line.txt
seq 1 5000 > many_short.txt                     # 5000 short lines
printf 'tests created: '; ls | wc -l

#!/bin/sh
# usage: ./matrix.sh "<your .c files, WITHOUT a main>" [function name]
# Builds with AddressSanitizer for every BUFFER_SIZE, runs every file in ./tests,
# and checks the output is byte-for-byte the input and the sanitizer is silent.
srcs=$1; fn=${2:-get_next_line}; bad=0
for bs in 1 2 5 42 9999 10000000; do
	cc -Wall -Wextra -Werror -g -fsanitize=address -D BUFFER_SIZE=$bs -DGNL=$fn \
		$srcs test_main.c -o matrix_bin || exit 1
	for f in tests/*.txt; do
		./matrix_bin $f > mo.txt 2> me.txt
		if grep -q "ERROR" me.txt; then
			echo "FAIL  BUFFER_SIZE=$bs  $f  $(grep -m1 -o 'ERROR: [A-Za-z]*' me.txt)"; bad=$((bad+1))
		elif ! cmp -s mo.txt $f; then
			echo "FAIL  BUFFER_SIZE=$bs  $f  output differs"; bad=$((bad+1))
		fi
	done
done
echo "failed: $bad"

bonus_main.c

cc -Wall -Wextra -Werror -g -fsanitize=address -D BUFFER_SIZE=5 ../get_next_line_bonus.c ../get_next_line_utils_bonus.c bonus_main.c -o bm

For the bonus: reads up to 8 files in rotation, one line each time around.

Usage: ./bm A.txt B.txt C.txt. The first file is tagged A, the second B, and so on; /dev/stdin works as a file name. Every printed line starts with its tag. Collect the lines of one tag and compare them with that file: they must be identical. When a file reaches its end it is closed and skipped; the program stops when all are done.

If your bonus function is not called get_next_line, build with -DGNL=name.

#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

#ifndef GNL
# define GNL get_next_line
#endif

char	*GNL(int fd);

/* usage: ./bonus_main fileA fileB [fileC]
   reads one line from each file in turn (A, B, C, A, B, C ...) and prints
   "<tag> | line". Compare each tag's lines with the file itself. */
int	main(int ac, char **av)
{
	int		fd[8];
	int		alive;
	int		i;
	char	*line;

	alive = 0;
	i = 1;
	while (i < ac && i < 9)
	{
		fd[i - 1] = open(av[i], O_RDONLY);
		alive++;
		i++;
	}
	while (alive > 0)
	{
		i = 0;
		while (i < ac - 1)
		{
			if (fd[i] >= 0)
			{
				line = GNL(fd[i]);
				if (!line)
				{
					close(fd[i]);
					fd[i] = -1;
					alive--;
				}
				else
				{
					printf("%c | %s", 'A' + i, line);
					if (line[strlen(line) - 1] != '\n')
						printf("\n");
					free(line);
				}
			}
			i++;
		}
	}
	return (0);
}

Reading a sanitizer report

the first lines are what matter

Read the top frame first (where it happened), then walk down the callers.

First line saysIt meansLook for
SEGV on unknown address 0x000000000000you used a NULL pointertrace it backwards: who put NULL here? A failed malloc, a freed-and-cleared pointer, a missing check
heap-buffer-overflowyou read or wrote past the end of a malloc'd blockthe size passed to malloc (+1 for the \0?), an off-by-one in a loop
heap-use-after-freeyou used a block after freeing ita pointer copied before a free; *left = rest; free(rest);
attempting double-freetwo owners freed the same blockwho owns it? one owner per block
LeakSanitizer: detected memory leaksa block was never freed and nothing points to itthe allocation trace lists where it was made: find the exit path that skipped the free
stack-buffer-overflowsame as heap, on the stacka local array indexed too far

If a leak is reported, the program exits without flushing stdout, so the last line of output can be missing. Fix the leak first; the missing line is a side effect.

ASan does not complain about reading uninitialised memory. For that use valgrind (school machines).

Compare with tick a question when you can answer it without looking

An evaluator can ask you to explain any line and to change the code live. These are the questions that come from your own design.

  • Why a static variable?edge
    expectread consumes bytes from the fd: they cannot be read again. What was read after the newline must be kept between calls, and a local would die at the return
    lifetime of a static: the whole program
  • What does the static point to?edge
    expecta heap string holding the bytes read but not returned yet; NULL at the start (statics start at zero)
    the pointer is static, the data is on the heap
  • Why must the buffer be malloc'd, not a local array?edge
    expectBUFFER_SIZE can be 10 million; the stack is about 8 MB
    the heap is limited by memory, not by the stack
  • What if read returns fewer bytes than BUFFER_SIZE?edge
    expectthat is not EOF (pipe, terminal, slow writer); only 0 is EOF
    so the loop condition is on the return value, not on the count
  • What does read return, in each case?edge
    expectn > 0 bytes read; 0 at end of file; -1 on error. It never adds a \0
    so you terminate the buffer at index n
  • Why free the old left after the join?edge
    expectthe join builds a new block; the old one has no owner left
    the helper consumes left
  • What happens if malloc fails in the middle?edge
    expectfree what you hold, return NULL, leave the static NULL; the next call starts clean
    the kit proves it
  • Why does substr return "" and not NULL when start is past the end?edge
    expectan empty string is a valid value (what is left after the last line); NULL would mean failure
    the two outcomes are different
  • How is the end of the file signalled?edge
    expectthe function returns NULL when nothing is left; the last line has no \n if the file did not end with one
    and the static is freed and set to NULL
  • Why do you stop reading as soon as you see a \n?edge
    expectnever read more than needed; the rest stays in left for the next call
  • What is the complexity with BUFFER_SIZE=1 on a very long line?edge
    expectquadratic: each join copies everything so far, and strchr rescans it
    you know the weakness and could fix it (scan only the new chunk)
  • (bonus) Why does one array of pointers count as one static variable?edge
    expectit is a single variable; its elements are the leftover of each fd
    and the index is the fd
  • Live change: BUFFER_SIZE=1, or a line limit, or return the line without the \nedge
    expectyou can point at the exact line to change and say what else it affects
